# 公式

这份文档说明**引擎实际在算什么**。每一节都对应实现里的一个函数，
并且给出可以口算核对的例子——计算器的价值一半在于"能核对"。

对应实现：

| 本节内容 | 实现位置 |
|---|---|
| 伤害公式 | `arkdps/damage.py` |
| 攻击力 / 间隔合成 | `arkdps/combat.py` |
| 技能循环 | `arkdps/rotation.py` |
| 机制常量 | `arkdps/rules.py` |

---

## 1. 三条伤害公式

游戏的伤害分三类，走三套完全不同的算法：

```
物理伤害 = max(攻击力 − 有效防御力,                 攻击力 × 5%)
法术伤害 = max(攻击力 × (1 − 有效法抗 / 100),       攻击力 × 5%)
真实伤害 = 攻击力
```

真实伤害不吃任何减免，所以打高防高抗目标时它的相对优势最大。

**5% 下限**对物理和法术都生效：攻击力再低也至少打出攻击力的 5%。
真实伤害没有这个下限——它本来就等于攻击力。

### 例：攻击力 1000 打三种目标

| 目标 | 物理 | 法术 | 真实 |
|---|---|---|---|
| 0 防御 / 0 法抗 | 1000 | 1000 | 1000 |
| 800 防御 / 0 法抗 | 200 | 1000 | 1000 |
| 2000 防御 / 0 法抗 | **50**（下限） | 1000 | 1000 |
| 0 防御 / 50 法抗 | 1000 | 500 | 1000 |

第三行的物理伤害是 `max(1000 − 2000, 1000 × 0.05) = 50`：
减防御减到负数时，靠的是下限而不是"0"。

## 2. 有效防御力与有效法抗

穿透类效果（「无视 30% 防御力」「无视 20 点法术抗性」）先折算成"有效值"：

```
有效防御力 = max(防御力 × (1 − 无视防御% / 100) − 无视防御固定值, 0)
有效法抗   = 法抗 × (1 − 无视法抗% / 100) − 无视法抗固定值
```

### 顺序很重要

百分比作用在**原始**防御上，固定值在**之后**扣：

```
防御力 1000，无视 50% 防御力，再无视 100 点防御力
  = max(1000 × (1 − 0.50) − 100, 0)
  = 400

如果反过来先减固定值：
  = (1000 − 100) × 0.5 = 450        ← 错了 50 点
```

### 法抗可以为负

有效防御力下限是 0（防御不能被削成"负防御"），但**有效法抗没有下限**：

```
法抗 20，无视 30 点法术抗性
  有效法抗 = 20 − 30 = −10
  法术伤害 = 攻击力 × (1 − (−10)/100) = 攻击力 × 1.10
```

负法抗意味着法术伤害**高于**攻击力。这是游戏机制，不是 bug，
所以实现里刻意没有对法抗做截断。

## 3. 攻击力怎么合成

这是最容易写错的一步。最终攻击力是：

```
攻击力 = 面板攻击力
       × (1 + 攻击力% / 100)      ← 百分比：**加算**
       × 攻击力倍率                ← 「提高至X%」：**乘算**
```

其中 `面板攻击力 = 精英2满级攻击 + 信赖加成 + 潜能加成`（都是加法）。

### 为什么必须区分

「攻击力+100%」和「攻击力提高至110%」看起来都在说"加攻击力"，但：

- **+100%** 是往括号里加 → `1 + 100%`
- **提高至110%** 是乘在括号外 → `× 110%`

两者同时存在时：

```
攻击力 1000，同时有「攻击力+100%」与「攻击力提高至110%」

正确：1000 × (1 + 1.00) × 1.10 = 2200
错误：1000 × (1 + 1.00 + 0.10) = 2100      ← 少了 100
```

多个百分比之间是**加算**（`+50%` 与 `+30%` 合成 `+80%`），
多个倍率之间是**连乘**（`×1.45` 与 `×1.1` 合成 `×1.595`）。

### 减法也要归一化符号

「攻击力−30%」和「攻击力降低 30%」是一回事，不管原文有没有负号：

```
「攻击力-30%」      → 数值里带了负号 → 攻击力% −= 30
「攻击力降低30%」   → 数值里没有负号 → 攻击力% −= 30
```

两种写法必须归到同一个结果。实现里按**关系词**决定符号，
而不是直接拿字面数值相加——后者会把"减攻"算成"加攻"。

## 4. 攻击间隔

```
攻击间隔 = (基础间隔 + 间隔修正秒数) × 间隔倍率 ÷ (1 + 攻速 / 100)
```

攻速（攻击速度）是**加算**的百分比，间隔是它的**除数**——所以攻速越高间隔越短，
但收益递减：+50 攻速不是"快 50%"，而是变成原来的 `1/1.5 ≈ 67%`。

### 三种写法对应三个不同的东西

| 原文写法 | 含义 | 落到哪个字段 |
|---|---|---|
| `攻击间隔缩短(-0.22)` | 减去 0.22 秒 | `interval_flat` |
| `攻击间隔缩短至70%` | 变成原来的 70% | `interval_mult` |
| `攻击间隔大幅度缩短(*0.2)` | **乘** 0.2 | `interval_mult` |

第三种最坑：`(*0.2)` 里的星号表示这是**倍率**。当成秒数会得到
"间隔 −0.2 秒"——数值看起来还挺合理，但正确答案是"间隔 × 0.2"，
两者差了 **5 倍**。

### 例

```
基础间隔 1.0s，天赋攻速 +12，技能「间隔缩短(-0.22)」

= (1.0 + (−0.22)) ÷ (1 + 12/100)
= 0.78 ÷ 1.12
= 0.6964s
```

被除数是 `(基础 + 修正)` 而不是 `基础`——修正和倍率作用的层次不同，
混在一起会让结果偏掉。

---

## 5. 段数与多目标

```
段数 = 覆盖值（若有） 否则 基础段数 × 段数倍率 + 额外段数
```

「攻击变为5连射」是**覆盖**（一共 5 段），不是"再加 5 段"。
实现里落到 `hits_override`，与 `hits_add` 分开——两者差一倍。

目标数单独记 `targets`。引擎算出的 `dps_cycle` 是**单目标**的，
`dps_cycle_total = dps_cycle × targets` 才是总输出。

有些技能写的是「同时攻击**阻挡的所有敌人**」而不是数字，打几个取决于
战场情况。这时落到 `targets_scope`，引擎按单体 1 计算**并明确标注**——
它不会假装知道。

## 6. 附加伤害

```
一次攻击总伤害 = 单段伤害 × 段数 + 附加法术伤害 + 附加真实伤害
```

附加法术伤害**同样受法抗影响**（这一点很容易漏），附加真实伤害不受任何减免：

```
附加法术伤害 = 攻击力 × 附加法术% / 100 × (1 − 有效法抗 / 100)
附加真实伤害 = 攻击力 × 附加真实% / 100
```

## 7. 技能循环

### 阻回

**技能持续期间技力停止回复。** 所以充能时间是**整段**的：

```
充能时间 = (技力消耗 − 初始技力) ÷ 技力回复速度
```

而不是"在循环里平摊"。这一点写错了会让短持续技能被严重高估。

技力回复速度取决于技能类型：

| 类型 | 速度 |
|---|---|
| 自动回复 | 1 点/秒（`GameRules.auto_sp_per_second`） |
| 攻击回复 | 常态每秒攻击次数 |
| 受击回复 | 假设的每秒受击次数（**外部输入**，默认 1） |
| 被动 | 不需要技力，充能时间为 0 |

注意「攻击回复」用的是**常态**攻速，不是技能期——技力是在技能冷却期间攒的。

### 四种形态

技能不是只有一种形状。混在一起算会得到荒谬的结果：

**① 持续型**（大多数技能）

```
循环时长   = 技能持续 + 充能时间
循环伤害   = 技能期DPS × 持续 + 常态DPS × 充能时间
循环 DPS   = 循环伤害 ÷ 循环时长
覆盖率     = 技能持续 ÷ 循环时长
```

**② 瞬发型**（`duration == 0`，如「下次攻击的攻击力提高至290%」）

技能只强化**一次攻击**，所以循环是"N 次攻击中有一次被强化"，其中 N = 技力消耗：

```
循环时长   = N ÷ 常态每秒攻击次数
循环伤害   = 常态单次伤害 × (N − 1) + 强化后单次伤害
```

把它按"持续 0 秒的技能"算会得出**无穷大** DPS。

**③ 无限持续**（黄昏、电流翻涌之类）

```
循环 DPS = 技能期 DPS        循环时长 = ∞        覆盖率 = 100%
```

**④ 形态切换**

这类技能没有"持续多久"，只有"当前在哪个形态"。引擎按
「开启后一直保持该形态」计算，**并明确标注这是个假设**——
实际强度取决于你什么时候切、切多久。

### 例：完整循环

```
干员攻击力 1000，间隔 1.0s，技能「攻击力+100%」，
技力 30 自动回复，持续 10s

常态 DPS = 1000 ÷ 1.0                    = 1000
技能 DPS = 1000 × (1 + 1.00) ÷ 1.0       = 2000
充能时间 = 30 ÷ 1                        = 30s
循环时长 = 30 + 10                       = 40s
循环伤害 = 2000 × 10 + 1000 × 30         = 50000
循环 DPS = 50000 ÷ 40                    = 1250
覆盖率   = 10 ÷ 40                       = 25%
```

## 8. DPH 的定义

**DPH = 一次攻击动作打出的全部伤害**，包含所有段与附加伤害：

```
DPH = 单段伤害 × 段数 + 附加法术 + 附加真实
```

多段攻击算的是**所有段之和**，因为"打一下"在实战里就是整个动作。
想知道单段多少，用 `dph_per_hit`。

DPH 和 DPS 是两个不同的东西，混了会让"谁更强"的判断反过来：

```
慢速高伤：攻击力 2000，间隔 2.0s
  DPH = 2000    DPS = 1000
快速低伤：攻击力 1000，间隔 0.5s
  DPH = 1000    DPS = 2000
```

前者 DPH 高一倍，DPS 却低一半。打高防目标时前者更优（每一下扣的防御更多），
打低防目标时后者更优。

## 9. 击杀耗时

```
击杀耗时 = 目标生命值 ÷ (循环 DPS × 目标数)
```

只在给了目标生命值时才有意义，否则是 ∞。

## 10. 帧取整（可选）

游戏逻辑以 30 帧/秒结算，攻击间隔实际会被量化到整数帧。
默认**关闭**（`GameRules.frame_rounding = False`），间隔保持连续浮点数。

开启后：

```
间隔 = max(1, round(秒数 × 30)) / 30
```

两者差别很小，但要比较两个干员的攻速阈值、或者需要精确到帧时，
就必须开启。

## 11. 建模边界

诚实列出来比假装没有好。以下情况引擎**不**做处理，或只做近似：

| 情况 | 现状 |
|---|---|
| 「第一天赋效果提升至N倍」 | 认不出来，标为待人工复核 |
| 「攻击变为群体攻击」 | 认不出来，标为待人工复核 |
| 「攻击装有N发子弹」 | 认不出来，标为待人工复核 |
| 浮游单元 / 召唤物的输出 | 不支持（只算干员本体） |
| 多段攻击中**各段倍率不同** | 不支持，按各段相同处理 |
| 附加伤害的独立暴击 / 独立倍率 | 不支持 |
| 条件效果（「但此时…」「对处于X状态的敌人…」） | **不参与计算**，单独列出 |
| 敌人属性被技能改变（如「敌人的攻击力-50%」） | 不套用到干员身上，标为待人工确认 |
| 部署费用、攻击范围、控制效果 | 判定为与 DPS 无关，不参与计算 |

导入器会把所有"认出来但没用上"的片段连同原文一起记进草稿的
`_unparsed`，并标注它**是否可能影响 DPS**。用 `arkdps coverage` 看全局情况，
用 `arkdps show 名字` 看某个干员具体卡在哪。

**刻意不做的事**：不猜。识别不出来就标出来，而不是套一个"看起来合理"的默认值——
静默的错误比缺失的数据危险得多。
